# 系统设置与碳铀模式

入口：侧栏「系统配置 → 系统设置」，地址 `console/#system`。

碳铀模式默认关闭。开启后，GM 可以在角色在线时直接写入数据库，不踢下线。设置保存到管理网关的独立设置记录，所有管理员会话共用，服务升级、浏览器刷新和重新登录后保留。

游戏内存不会同步刷新，后续游戏存档可能覆盖修改。重名、物品 ID、数量、PVF 代次、所属账号、数据版本和永久回执仍按各自业务规则处理。

覆盖 13 类操作：库存、任务、角色改名、冒险团改名、栏位、转职、副职业、等级、SP/TP、金币、账号仓库、单批邮件删除、分批邮件清理。邮件发放、福利规则、公告等原本支持在线操作的功能保持原流程。

确认框不再提供逐次「强制执行」勾选。模式关闭时显示前往系统设置的提示；开启后仍只确认本次修改一次。

## 接口与持久化

- `GET /api/v1/settings/system` → `data.carbonMode`。
- `POST /api/v1/settings/system`，JSON `{"carbonMode": true}` 或 `false` → 保存后的状态。沿用 GM 登录与 CSRF。
- 能力：`features["system.settings"]`。旧网关不提供时，页面显示升级提示。
- 存储：现有 SettingsRepository 的专用 scope `purplemagic:management:system`；无需新增表，不修改游戏活动或玩家设置。
- 每次相关写入在取得资产锁前读取一次设置，整次事务使用同一个快照。开启模式无需任何游戏私有运行态调用。

## 本次读取与刷新审计

定位并调整 9 类重复读取路径。它们多数是模块级重复请求，不是每次都加载整个数据库。

| 路径 | 原行为 | 当前行为 |
| --- | --- | --- |
| 库存保存/替换/批量删除的预览 | 再读已经打开的物品详情；批量串行读取 | 复用当前详情，缺失项最多 4 个并发；服务端预览核对版本 |
| 库存保存成功 | 角色、金币、点券、整个当前库存分类重新读取 | 回执更新/删除对应槽位；打开的受影响详情按需读取 |
| 强制执行勾选 | 再签一次完整预览 | 移除逐操作勾选；设置开关只保存一次全局配置 |
| 改名、成长、金币/点券提交 | 角色资料 + 成长 + 所有流水 + 发放任务 | 改名按回执更新；成长和余额仅刷新受影响字段 |
| 任务、邮件删除、公告提交 | 额外读取当前角色和余额，再刷新整个页面 | 任务当前筛选、邮件对应行、公告当前页分别更新 |
| 选角色、切背包分类 | 页面与外层导航均可能发起库存读取；角色选择附带余额 | 库存由页面独立加载；余额进入资产页再读取 |
| 静态物品/任务搜索缓存 | 任意 POST（包括预览）清空 | 玩家写入和预览保留；退出和 PVF 设置变更失效 |
| 网关 PVF 查询缓存 | 每次读取元信息；职业反复传输/解析；物品缓存满即全清 | 元信息与单职业资源按完整 PVF 哈希缓存；物品缓存仅逐项淘汰 |
| 账号点券显示 | 加载账号全部元数据，含历史回执 | 单条 SQL 读取余额与版本两项，未实现投影的仓储兼容原接口 |

改名成功后不再查询职业资料或流水，因此无关读取超时不会被显示成改名失败。连续两次改名以第一次成功回执中的名字作为第二次的原名。非法名称和已占用名称继续返回对应原因。

扩展写操作的刷新范围集中在 `gm-console/src/api/refresh.ts`。新增操作优先使用回执更新已有行，需要再读时在该文件登记具体资源，不调用全页刷新。

## 验证范围

前端请求计数验证连续改名每次只有一次预览、一次提交；已打开物品保存复用详情，不拉全库存；设置变更不重签待确认操作。一次性 MariaDB 覆盖单双分片在线改名、连续改名、重名拒绝、开关持久化与关闭恢复、在线物品删除及幂等、两字段钱包投影。生产验收使用 HTTP 只读与静态版本回读。
