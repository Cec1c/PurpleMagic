# 反作弊

侧栏 **反作弊** 独立于角色选择，入口 `/console/#anti-cheat`。

## 通关统计

按角色、地下城和难度统计成功结算次数，默认查看最近一天，可查询最多 31 天的时间范围。列表默认按次数降序排列，每页 50 条。点击表头中的字段名切换升序／降序，包括角色名、角色 ID、账号、地下城名称／ID／难度、次数、最快／平均耗时、疲劳消耗／平均每次、小时峰值和最近通关。排序覆盖整个筛选结果，切换后从第一页显示；相同值使用固定身份顺序，未采集值始终排在末尾。

耗时由游戏服务端接受入场与确认通关的时间计算。重复结算按角色与完成键去重，记录随角色结算事务一起提交；失败事务不会留下成功记录。统计从采集启用后开始，旧存档中没有完整历史的局次不补造。

耗时阈值默认 30 秒，频率阈值默认每小时 60 次，可在页面调整并筛选。峰值统计同一角色、地下城和难度；筛选时间边界上的小时只统计范围内的记录。阈值用于人工复核，不自动判定作弊或自动封禁。页面可从统计行直接选择封禁对应账号。

### 疲劳消耗

每行显示成功通关局次的实际疲劳消耗总和、已采集局次的平均每次消耗，以及“已采集局数／通关数”。上方卡片汇总当前页已采集疲劳。

游戏在普通房间、每日副本、史诗入场和公会副本的扣除事务成功后累计本局消耗；最后一点疲劳耗尽后继续走图、重复进入已计费房间不会增加消耗。疲劳药和每日恢复只补充余额，不冲减本局消耗。通关记录与结算同事务保存，失败／退出局不计入通关统计。

疲劳采集从配套版本启用后开始。已有通关历史保留，尚未采集显示“—”；真正免疲劳的成功局显示 `0`。混合新旧记录时，总和与平均值仅使用已采集的局次。

## 封号与封 IP

- **账号封禁**：查询账号名、账号 ID 或 IP，查看最近登录 IP 与注册 IP，选择账号或最近登录 IP 后填写原因、期限，确认一次执行。
- **IP 与封禁记录**：直接输入 IPv4 或 IPv6 地址，查看现有封禁、到期时间和原因，解除或重新封禁。IP 精确匹配单个地址，IPv4 映射 IPv6 会规范成同一目标。
- 期限可选 1 小时、1 天、7 天、30 天或永久。到期后准入检查自动放行；无需后台任务手动解封。
- 账号封禁阻止该账号登录与进入游戏，撤销其凭证并断开当前游戏连接。IP 封禁阻止对应来源注册、登录和进入游戏，断开匹配的在线连接；共用出口 IP 的其他玩家也会受影响，确认框展示具体 IP。
- 登录器 IP 仅由受信任的玩家网关传递；游戏连接使用服务端取得的远端地址。
- 操作结果暂未收到时，页面保留原请求编号，重新打开模块可继续查询或重试。旧请求重放不会覆盖后来完成的解封或封禁。

两个封禁页签也支持点击各字段排序，包括账号、IP、登录限制，以及封禁目标、状态、原因、到期和更新时间。永久封禁的到期时间排在末尾。

早期工具设置的账号 `disabled` 状态仍独立生效，账号列表标为“已限制登录”。本模块的解除操作解除对应的新封禁记录。

## 接入与数据库

外部 GMService 与私有 PlayerGateway 提供：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/anti-cheat/clears` | 时间范围、角色/账号 ID/地下城关键词、耗时或频率筛选 |
| `GET /api/v1/anti-cheat/accounts` | 账号与登录/注册 IP 查询 |
| `GET /api/v1/anti-cheat/bans` | 封禁记录分页 |
| `POST /api/v1/anti-cheat/bans` | 带请求编号、当前版本、原因和期限的封禁/解封 |

GET 查询支持 `sortBy` 与 `sortOrder=asc|desc`，字段按资源校验；未知字段或方向返回 400。通关结果新增 `fatigueSpent`、`averageFatigue`（均可为 null）及 `fatigueSamples`。

管理接口沿用会话、CSRF 和来源校验，玩家公网网关不开放这些路径。游戏私有 API v1 新增 `clear_stats`、`moderation_accounts`、`bans`、`change_ban`，共享契约为 `internal/modules/dnf/moderation`。

需要配套游戏端：在每个角色写入分片新增 `<prefix>clear_history`，注册库新增 `<account-table>_bans` 与 `<account-table>_ban_receipts`。通关表增量增加可空的 `fatigue_spent BIGINT`，旧记录保留 NULL；每次启动迁移可重复执行。启用仓储 `auto_create_schema` 的实例随游戏启动增量建表；关闭自动建表的实例须先应用配套游戏源码的 schema。原规则、玩家资产、永久回执和队列保持。

部署顺序为配套游戏服务端、PlayerGateway、GMService 与 `gm-console/dist`。功能属于纯服务端与管理页面变更，不新增客户端协议。源码、测试、部署和原生游戏验收分别记录在对应发布回执中。
