# 提交后的游戏邮件通知

邮件资产及任务进度成功提交后，PlayerGateway按永久投递回执中的实际收件角色，调用游戏私有管理API的 `notify_mailbox`。单封邮件、版本化任务、旧福利、自动扫描及补发都使用相同通知路径；扫描按页汇总并去重。

游戏端需要具备 `notify_mailbox` 消费者。外部GMService负责队列和转发，实际数据库消费者在游戏侧PlayerGateway，不能只更新外部页面就认定新行为已经生效。

通知有整体超时并在提交后执行。通知失败、离线或浏览器断开不撤销已提交邮件，不重复发放物品；已有永久回执和任务revision保持。离线收件人在后续登录或加载时重读未读数。`online` 表示会话投递资格，不表示玩家图标已经显示。

验证覆盖外层事务提交成功/失败、回执实际角色、重复回执、超时、离线和通知失败后的资产保持。SQL测试驱动、内存仓储及本地HTTP的范围单列；临时MariaDB回归用于原持久福利合同。没有新增持久通知队列或崩溃后的必达承诺。
