参考 A12→A21、client-text 迁移及 SQLite 修补属于源格式专用工具；当前 MariaDB 如需迁移，另列输入、输出和转换规则。自动入会插件属于游戏规则，尚未作为 GM 管理操作纳入。

S 的安卓邮件页用于移动交互参考：切换收件角色、按物品名/代码检索、分类、数量编辑和发放入口。当前继续同一 Web 前端的响应式实现，整体视觉沿用已确认的 页面布局与主题编辑。

### PVF 更新适配

- 索引由完整 PVF SHA256 与解析/格式版本共同标识；相同 ID 也不能跨代复用旧详情。
- 离线构建临时文件并校验后原子发布；取消、损坏或解析失败保留上一代及错误结果。
- GM 使用已校验的指定代次；更新后重开该代次，请求不全量扫描 PVF。响应记录摘要，静态分页游标绑定代次。
- 新 PVF 缺失的玩家物品/任务保留真实 ID 与存储状态，显示“当前 PVF 未收录”。
- 回归覆盖同 ID 内容变化、新增/删除、版本变化、旧索引、损坏和取消；新版真实 PVF 另留离线验收回执。

## 查询和缓存设计

| 数据 | 读取与刷新方式 |
| --- | --- |
| 物品、任务、职业等 PVF 定义 | PVF SHA256＋解析版本决定索引代次；离线生成，按条读取。物品详情、任务索引已实施；其他目录继续补齐 |
| 账号/角色目录 | 查询提交和分页时读取基础列；复用现有有界分页 |
| 背包、仓库、邮箱、角色任务 | 打开对应页签时读取；显式刷新；列表与详情分离，显示读取时刻。读取范围下推到数据库，避免先全量加载再截取一页 |
| 短时间重复读取 | 合并同目标在途请求；若启用缓存，限定字节容量、有效期及目标/容器范围，手动刷新重新取数 |
| 管理写操作 | 提交时读取权威状态，核对版本及归属；成功后使受影响的角色/账号视图失效。账号金库变化使该账号下共享视图一起失效 |
| 在线状态 | 按需查询游戏服务；失败显示未知，保留与数据库存档读取时刻的区别 |
| 统计与异常核查 | 时间范围、游标分页与预聚合；后台采集有批量、保留期限和配额 |
| 对外玩家展示 | 默认每天生成低优先级磁盘快照，公开请求只读已发布快照 |

旧读取入口的源码问题与新版处理：

1. `handleItemList` 每次加载角色所有槽位并合并账号共享背包，再构造全部响应；角色/共享背包读取失败时可能返回空或不完整结果。新接口已按容器在 SQL 分页，读取失败返回 503。
2. `inventoryRowPayload` 的部分实例字段仍使用固定值，例如 `serial`、`seal`；新详情已从实际记录及已验证的实例解析器取值，缺失值显示未知。
3. 旧页面选择角色时调用属性、点数、成长选项及背包等加载函数。部分旧任务函数已被 `gmtool-scope.js` 替换为空实现，不能把这些调用全部计算成数据库请求。新界面只加载当前展开页签。
4. `questCatalog` 首次访问在锁内使用 `context.Background()` 构建完整任务目录并保留结果；新版静态查询已使用离线压缩任务索引，旧任务写操作仍沿用原目录加载路径。
5. 旧任务总览构造全部进行中/已完成响应；底层 `Quest.Load` 读取状态和扩展字段。新查询已使用专用读取投影，将状态筛选及分页落实到 SQL。
6. R 的管理页面未发现持续 `setInterval`；其公告补丁默认每 3 秒轮询，部分角色查询无分页。分别评估页面请求、后台任务与单次查询规模。
