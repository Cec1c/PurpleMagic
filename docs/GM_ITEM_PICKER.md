# 邮件与福利物品选择器

邮件右侧输入物品的部分名称或完整 ID，结果显示名称、ID、有效期。同名物品分别列出。

- 默认一次显示300条，可切换500或1000条；查询会自动接续现有100条游标接口。需要更多结果时，点击列表内“再显示”继续读取一批。
- 邮件可逐项添加，或跨搜索勾选多种物品后一次加入附件。添加数量可统一指定，加入后每种附件可单独修改。同一ID再次加入会累加数量，最多99999；不同ID不会因名称相同而合并。
- 福利规则选择“指定道具”后使用相同列表，点击“选用”填入该规则；一条规则仍发放一种道具，也可直接填写ID。
- 搜索变化会取消旧请求，已选物品保留。读取失败保留已加载结果和游标，重试可继续；加载圆圈与结果区占用固定空间。

实现仅调整静态前端，复用现有认证物品查询接口与PVF索引，不修改邮件、福利或游戏服务事务。

## 多附件发放

加入附件后点击发送，确认框会列出收件角色、每种物品的 ID、数量和实际到期时间。确认一次后，支持后台队列的部署会保存发放任务；全部提交后可关闭页面，在“发放记录”查看进度。每种附件单独一封邮件，金币只随第一封。

整批预览只读取一次当前 PVF 版本，最多同时预览4种附件，仍逐项核对物品参数和收件名单。确认时直接提交已有任务到持久队列，页面不再逐批等待投递，也不重复刷新角色资料。网络中断后继续查询原任务，已接收的任务复用原回执。未提供后台队列的部署保留原有连续发放方式。

`gm-console/tests/mail-performance.test.mjs` 覆盖并发上限、名单核对、附件顺序、金币与期限、后台提交、丢响应恢复和重复点击。12种附件的隔离延迟对比（普通请求80ms、同步发放1910ms）：预览36次请求减为25次，确认36次减为12次；测得预览3.40s→0.65s、确认25.24s→1.13s。这是前端请求路径对比，实际投递进度由后台记录。
