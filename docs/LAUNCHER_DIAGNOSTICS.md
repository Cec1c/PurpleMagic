# 登录器增强诊断

设置 → **增强诊断日志** → 打开开关 → 阅读说明并同意。随后正常启动游戏即可。

- 每次游戏启动独立记录，双开分别显示；只保留最近 **5 次**。
- 每份日志旁边点击 **导出**，Windows 弹出 **另存为**，选择位置和文件名后保存为 **`.log`**。
- 运行中的日志也能导出。取消另存为不会写文件，关闭诊断后仍能导出已有记录。
- 同一个游戏进程重新开启诊断或重开登录器，会续写原启动日志；游戏重新启动则创建新日志。
- 默认关闭。主界面开启状态可见，偏好随其他设置一起持久化。

日志是 UTF-8 文本，每行一个 JSON 对象，包含版本头、事件/采样和末尾汇总。可以直接用文本编辑器打开，也可交给分析工具。取消问题类型、窗口选择、标记、倒计时、片段勾选等玩家操作；专项采样自动识别适配场景。

## 2026-10-21：异常栈与游戏操作

本轮候选保持一个开关、每次启动独立日志、最近五次及原生另存为 `.log`。开启时先显示采集说明，点击“同意并开启”后保存 `consentVersion=1`。旧版已开启诊断的偏好迁移为关闭，重新同意后才扩大采集范围；Host 同样校验同意版本。

- **登录器异常**：保存错误类别、HResult、Win32/Socket/HTTP 数值及最多六层内部错误、每层至多 32 个方法栈帧。消息、Data、文件名、URL、参数值不进入导出。NativeAOT 移除的方法元数据标为 `unknown`。更新在登录前失败也会形成可导出的日志。
- **游戏异常**：独立的同名核心辅助进程通过 Windows 调试接口关联 PID、创建时间和客户端路径均匹配的目标。异常交给游戏原有处理器；只处理调试器初始关联断点。保存常见 SEH 首次通知以及未处理异常的异常码、线程和至多 64 个“模块文件名 + 模块内偏移”栈帧，不生成内存转储、不下载符号。首轮异常可能由游戏自行处理，`first_chance=1` 不等于闪退；`first_chance=0` 表示未处理通知。每个采集器最多 16 次首轮和 2 次未处理通知，后者有独立额度。
- **玩家操作**：Windows Raw Input 只读取目标游戏为前台时的输入。每秒汇总方向键按下、其余键的匿名按下次数、鼠标按钮、移动活动和滚轮次数，另记焦点变化。按住键的重复事件合并；不记录字母/数字键值、按键文字、鼠标坐标或聊天内容。它记录操作活动，不包含任务完成、技能命中、物品获得等服务端业务结果。
- **权限**：先使用当前权限。系统拒绝关联时，面板出现“提升诊断权限”，点击后仅辅助进程以 `runas` 请求 Windows UAC；登录器和更新程序继续原权限。取消 UAC 后恢复普通采集，不重复自动弹窗。
- **停止**：关闭开关、改变客户端目录、退出登录器会通知采集器刷新并脱离；父进程异常退出由管道断开和父 PID 检查触发脱离。`DebugSetProcessKillOnExit(false)` 保证采集器退出不终止游戏。没有持久调试器或 WER 注册表配置。

调试关联会使目标的 `IsDebuggerPresent` 为真；异常采栈时短暂停住目标。32/64 位隔离子进程已验证，正式游戏的兼容性、实际 UAC 和实机输入仍单独验收。未知 EXE 可以使用这些 Windows 通用能力；AT-5T 专项仍只对下表已验证布局启用，本轮未增加 EXE 哈希白名单、逐帧记录或服务端事件关联。

辅助进程只通过当前用户命名管道通信，双方核对管道对端 PID、父进程创建时间及相同核心程序路径；目标指令不走命令行。每个实例分别持有采集器和有界队列。`observed_unix_ms` 是辅助进程实际采集时间，区别于主日志收到该记录的时间。

新日志 envelope 为 `schema_version=3`，记录定义见 [record-v2.schema.json](diagnostics/record-v2.schema.json)。旧日志续写保留原创建头，最新格式以末尾汇总为准；分析器同时读 2/3。10 MiB 上限中普通采样预留 512 KiB 给异常和最近操作，另为最终未处理异常与汇总保留空间；截断状态保持明确。数据只保存在本机，由玩家手动导出分享。

## 自动采集

基础记录覆盖更新结果、客户端与频道检查、账号 API 状态码、进程创建/退出、每秒性能摘要。启动失败也记录对应启动尝试。AT-5T 场景命中后自动开始最长 30 秒的专项采样，默认目标间隔 5 ms，记录实际间隔及读取耗时；离开场景结束专项。

进程关联核对 PID、创建时间、EXE 路径和 Windows 用户会话。最多自动关联本客户端目录的两个游戏实例；私有进程登记文件用于恢复关联，路径和窗口标题不进入导出。

采样、哈希、后台落盘、UI 通知分离。每秒提交一批完整记录，游戏退出、关闭开关、关闭登录器和导出时刷新。未知 EXE 记录基础项目及 Windows 通用异常/操作；完整 SHA256 匹配后才启用 AT-5T 内存布局。

## 字段与版本

布局模块：`at5t-readonly-1`。完整 EXE 大小均为 `111812608` 字节。

| 版本 | EXE SHA256 |
| --- | --- |
| V135 | `8de790c1974fe74d3b74ec6095b7281ea337759a4adcdfebdd874bf67a94126f` |
| V141 | `26abf551753c2745c2e5b349fb24336422a189187ff847c995e0df9a68871079` |

其他摘要继续记录基础日志，专项显示“不支持当前版本”。地址按实际模块基址重定位。

| 字段组 | 读取依据及含义 |
| --- | --- |
| `identity.*` / `actor.address` | 本地 primary、override、VirtualCharacter；override 读取失败时不回退 primary |
| `actor.*` | 场景、虚表及三个入口、ride、ride_lock、保护动作；保护字段及密钥链二次读回，密钥不输出 |
| `descriptor.*` | 角色 `+3DE0` 的描述符、使能 `+30`、状态 `+2C`、mode `+28`，角色 input 注册关系 |
| `rule.*` | 描述符 `+4/+8` 的 28 字节规则行；嵌套逻辑键向量、`condition_10` 原始条件值、有符号 `minimum_duration`、`time_window`；按游戏规则顺序输出 |
| `input.*` | 角色独立 input `+643C`、回退源、四个过滤等级 `+4C..58`、过滤旁路 `+84`；过滤等级不是队列长度 |
| `logical4.*` | 游戏输入记录中的 logical 4 行；原行序号、time `+4`、held_duration `+8`、down `+C`、fresh `+D` |
| `vehicle.*` | 当前场景至多 8 个 61235 对象；owner/rider、交互状态、锁、模式、动作与位置 |
| `*.x/y/z` | physics `+B8` → 位置向量 → 已验证 `0288E950` getter 的浮点位置；委托 physics 或未知 getter 明确为 unsupported |
| `*.distance_xy/scaled` | 根据同次稳定采样的实时位置计算欧氏距离及 Y 比例校正距离；比例来自 `057C2918`。这是计算值；游戏内部整数舍入后的 distance 调用结果单列 unsupported |

对象槽位/标记、身份指针、向量头、嵌套规则内容、physics 坐标和保护字段均有稳定性检查。变化中的合成快照标为 `unstable`，成功数值改为 null。对象及规则变化通过完整/差量快照的序号与时间定位。场景列表每 250 ms 或身份变化时刷新；高频样本不反复输出不变对象身份。

字段边界：场景 4096 槽、最多 8 辆载具、规则 32 行、每规则 32 逻辑键、注册 4096 行、硬件输入 1024 行、最多 32 条 logical4 行。超过边界记录失败或限制原因。

来源：ServerS5A3 已审阅只读采样器 `87861a0`（上游合并 `8ead65a`）；V135 原生规则/physics 契约与 V141 代码窗口对照。新增位置 getter、虚表和舍入函数窗口另外完成 V135/V141 逐字节比对。字段端口实现自包含于 `launcher/Engine/Diagnostics/`，构建不读取相邻游戏源码。

## 存储与导出

| 项目 | 行为 |
| --- | --- |
| 每游戏缓存 | 环形缓存 2 MiB，待写批次 512 KiB |
| 写入队列 | 2 个等待批次 + 1 个写入批次；每批最多 512 KiB |
| 单份日志 | 10 MiB；达到上限保留完整行，汇总标明截断 |
| 本地保留 | 按游戏启动时间保留最近 5 次；不按导出时间或 7 天删除 |
| 导出 | 选定一份启动日志，刷新后原子写入用户选择的 `.log` 路径 |
| 覆盖 | 原生窗口确认覆盖；写入完成后替换，失败保留原目标 |

日志位于用户状态目录的 `diagnostics/logs/`，每份配套一个本地索引。中断写入恢复到最后持久化索引对应的完整记录。导出副本不参与自动清理。旧候选的 `clips/*.zip` 保留为历史文件，当前界面只使用启动日志。

每份 `.log` 的第一行 `type=log_header`，最后一行 `type=log_summary`，`schema_version=3`。中间使用 [record-v2.schema.json](diagnostics/record-v2.schema.json) 的事件/采样/异常行；同一次启动序号和单调时间递增。专项完整快照至少每秒一次，差量通过 `base_sequence` 关联。

汇总包括 EXE/PVF 实际完整哈希、预期 PVF 哈希、签名序号、已保存行数、丢样/读取失败/截断与未接入字段。只输出白名单字段；密码、Token、完整启动参数、聊天、账号和安装路径不进入日志。服务端事件尚未接入，汇总记录 `server_events_connected=false`。

```powershell
python scripts/analyze_diagnostics.py docs/diagnostics/diagnostics-synthetic.log
```

分析器也支持历史 ZIP。新的 [合成日志](diagnostics/diagnostics-synthetic.log) 不包含玩家数据。

## 接口与兼容

Flutter 保存 `diagnostics.enabled`；旧 `problemType` 偏好可继续读入，采样统一按自动模式。Host 的 `diagnosticExport` 参数是 `sessionId` 和原生另存为返回的完整 `path`；`diagnosticElevate` 仅接受当前待提升权限的 `sessionId`。导出独立于更新/登录操作锁。

便携外层程序名为 **PurpleMagic.exe**。内部 bootstrap、Flutter/Core 文件名、产品标记、缓存目录和签名更新契约继续沿用。自动目录发现新增 `.client/`，并保留 `client/`、直接客户端根目录及手选目录优先级；候选须包含非空 `DNF.exe` 和 `Script.pvf`，版本哈希由更新与启动校验。

本轮使用隔离 profile 完成构建和验证，迁移配置及实际交付记录见私有交接。验证范围见 [验证记录](diagnostics/VALIDATION.md)。
