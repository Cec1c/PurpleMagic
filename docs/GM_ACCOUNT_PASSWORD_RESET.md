# GM 随机密码重置

进入 **账号与角色 → 账号**，在目标账号行点击 **重置密码**。核对账号并确认一次，结果窗口显示 20 位随机密码，可点击 **复制新密码** 交给账号本人。角色为空的账号也可重置。

重置会使目标账号退出登录，旧密码、登录令牌和未使用的 QQ 绑定码失效，并清除密码错误冷却。QQ 绑定、封禁状态、角色、资产及福利回执保持。

新密码只保留在当前结果窗口。关闭或刷新页面后需要重新执行重置才能取得新的随机密码。网络中断时保留窗口，点击 **重试本次重置**：沿用同一请求和密码，游戏服务通过持久回执核对结果。若玩家随后自行改密，旧请求会提示密码已再次修改。

## 接口与存储

- 管理接口：`POST /api/v1/accounts/{accountId}/password-reset`，使用管理会话、同源检查及 CSRF。
- 请求：`requestId`、确认的账号名 `account`、浏览器 Web Crypto 生成的 20 位随机 `password`（120 位随机性）。密码放在 JSON 请求体内，经 HTTPS 管理入口与私有游戏管理链路传输。
- 私有游戏 action：`reset_account_password`。响应只包含请求编号、账号标识、账号名和时间，不回传密码。
- 账号标识和账号名必须同时匹配。按玩家改密相同的锁顺序执行，密码更新、令牌/绑定码撤销、冷却清理和回执写入在同一数据库事务中完成。
- 游戏账号表新增 `<account_table>_password_resets`：保存请求编号、账号标识、请求摘要和时间。只保存密码的 bcrypt 哈希及不可逆请求摘要，不保存明文密码。游戏启动时幂等建表。
- 重试不再次踢出使用新密码登录的连接。重复请求改变目标或密码会返回冲突。
- 此操作绕过普通资产操作的浏览器恢复存储与任务结果持久化；新密码不进入 localStorage、sessionStorage、日志或操作导出。

## 接入与验证

先累计更新支持该 action 的游戏服务，再更新管理端与 `gm-console/dist`。需要重启游戏服务的发布交 Syncer，按用户批准的累计窗口执行。

验证覆盖管理鉴权/CSRF、私有接口、账号匹配、旧密码与令牌撤销、QQ 绑定保留、冷却清理、同请求并发和重试、后续改密冲突、事务失败回滚及其他账号隔离。数据库验证使用一次性 MariaDB。
