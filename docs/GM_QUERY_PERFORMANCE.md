# GM 查询、任务库与 PVF 数据模式

查询区新增「PVF 物品库」和「服务器活动」。物品可按名称、ID、类型分页搜索并查看文本、属性和条件；活动同时显示配置状态、游戏进程实际状态和是否等待重启。活动接口只读，不修改活动开关。

任务库可在没有当前角色时浏览。选择操作角色与任务后，一次确认执行；确认页固定最终角色名单，每个角色使用原有任务事务和独立回执。响应丢失时沿用原幂等键重试，已经取得回执的角色不会重复执行。完成任务不发放任务奖励。每次最多 100 个角色、100 个任务；角色在线保护、任务准入和版本检查仍由游戏管理网关执行。

## 查询生命周期

- 账号目录先展示一页账号及角色数量；点券余额以最多 4 个并发 GET 补齐，角色列表在展开账号或选择账号目标时读取。20 个账号的首次请求数由 42 次降至 21 次。
- 背包容器并发读取并逐步展示；单个容器失败仍保留其他结果。成长和流水并发读取各领域，邮件、成长、福利、流水只在对应页签打开时读取。
- 切换页面、页签或角色会取消旧范围的读取。旧请求不能修改新页面或延长新页面的加载圈；搜索也取消上一轮结果。
- GET 截止时间为 12 秒，覆盖并发队列、网络和 JSON 正文；写请求为 45 秒，超时后保持原确认数据及回执恢复流程。导航不会取消提交中的 POST。
- 错误保留已成功显示的数据，重试补读失败部分；需要聚合版本的容器、成长、流水重试重新读取该资源。
- 仅 PVF 列表和单条定义视图使用 20 秒、最多 32 条的内存缓存。角色资产、操作准备读取、版本及回执始终读取服务端；写入和退出登录清除视图缓存，HTTP 仍使用 `no-store`。

## PVF 数据模式

「公告与下载源 → PVF 数据模式」提供磁盘索引与直接加载 PVF。该设置使用 GM 登录和 CSRF，不需要 Hub 凭据。

磁盘模式为默认值。直接加载在外部 GM 进程内后台打开同一份完整 SHA256 的 PVF，预热常用目录；加载期间继续使用磁盘索引，成功后切换读取来源，失败则展示原因并保留磁盘服务。切回磁盘模式后移除内存归档引用，已有读者完成后由 Go 回收。加载并发固定为一次；已取消的加载不会覆盖磁盘选择。

内存模式保留完整归档、目录、字符串表，另限制解码块缓存为 64 MiB、文本缓存为 32 MiB，各最多 512 条；磁盘源自身的 14 MiB 有界缓存仍存在。物品/任务列表继续使用同代索引，物品详情在内存模式直接解析当前 PVF。该模式加速定义读取，不改变账号数据库或公网往返耗时。

GMService 配置增加可选 `pvfModeStatePath`，默认 `queuePath + ".pvf-mode.json"`。此文件须可写、保持私有，并跨发布保留；保存内容只有模式和完整 PVF SHA256，不修改服务凭据。服务重启恢复同代选择，PVF 摘要变化后回到磁盘模式。

| 接口 | 所属服务 | 行为 |
| --- | --- | --- |
| `GET /api/v1/activities` | 私有游戏管理网关，外部 GM 认证转发 | 读取活动状态 |
| `GET /api/v1/settings/pvf` | 外部 GM 本地 | 读取当前/期望模式、加载状态、摘要及错误 |
| `POST /api/v1/settings/pvf` | 外部 GM 本地 | `{ "mode": "disk" }` 或 `{ "mode": "memory" }`；保存并异步切换 |

游戏网关拒绝 PVF 设置路由；管理 API 不挂到玩家监听。部署需同时更新外部 GM、管理网关和 `gm-console/dist`，保留现有批准 PVF、六类索引、会话、福利规则、队列和回执。

## 验证入口

- `npm test`、`npm run build`（`gm-console/`）：取消、超时、并发上限、旧搜索、部分失败、缓存范围、多角色回执恢复。
- `go test -race ./internal/platform/pvf ./internal/services/gmtool -run 'TestModeSource|TestV1QueriesAuthentication'`（`gateway/`）：模式恢复、加载中切回、失败回退、hash 校验、并发读、认证/CSRF/服务边界。
- `python gateway/scripts/test_mysql.py --queries-browser-script gm-console/tests/queries-browser.py`：真实 HTTP、一次性数据库，注入点券读取延迟/失败，浏览器查询、多角色任务与深浅主题验收。浏览器中的模式控制是测试桩；归档实际切换由平台测试单独验证。
- 可用 `PURPLEMAGIC_PVF_MODE_TEST_PATH`、`PURPLEMAGIC_PVF_MODE_TEST_INDEX`、`PURPLEMAGIC_PVF_MODE_TEST_SHA256` 显式传入批准资产，运行 `go test ./internal/platform/pvf -run TestModeSourceApprovedPVF -count=1 -v`。只读原资产，记录堆内存、加载耗时及两种模式的内容一致性。

源码测试、部署与正式入口验收分别记录；本文件描述实现，不代表部署完成。

2026-10-20 本地验收：40 项前端测试、178 项 MariaDB 测试（68 个顶层测试）、双 Go 模块 list/test/vet、Windows/Linux 构建与边界检查通过。最终构建另跑真实 HTTP 浏览器查询/福利验收，零页面 JS 错误；20 账号在每次点券读取注入 200 ms 延迟下，约 0.36 秒展示基础行、1.69 秒补齐，21 个 GET、并发峰值 4，切任务页约 0.05 秒结束加载。这是隔离环境的结果，正式入口耗时由部署后回读确认。
