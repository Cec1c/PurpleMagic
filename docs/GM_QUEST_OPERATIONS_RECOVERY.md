# 任务操作与恢复

在“任务”中选择当前角色的任务，或从任务库选择多个操作角色，点击完成或恢复。确认框固定角色名单和任务；完成操作只改变任务状态，不发放任务奖励。

提交后可以点击右上角关闭、按 Esc 或点击“收起”。顶部“操作回执”显示已完成步骤数，点击可重新打开。当前标签页刷新后仍保留操作、固定名单和回执；刷新不会自动再次提交。点击“继续并查询回执”使用原请求编号，已经完成的角色会跳过。

遇到角色/任务版本、PVF 版本或在线状态冲突时，可以选择“重新预览未完成项”。已经成功的角色回执保留；剩余角色读取当前状态后，再确认一次执行。连接中断或结果未知的请求继续使用原编号恢复。

操作弹窗的背景点击不触发关闭，避免点到弹窗边缘使页面消失。关闭浏览器标签页会结束本次标签页的恢复记录；已提交的永久流水可在管理记录中查询。

## 存储与诊断

任务管理事务仍保留账号/角色锁、目标角色离线检查、完整版本校验，以及任务状态和永久回执同事务提交。仅在任务管理事务中启用差量保存：比较本次加锁读取的快照，按角色、状态组、任务 ID 删除和写入变化行，单批最多 200 条。普通游戏仓储的整份保存契约保持。

这避免了完成一个任务时重写角色全部历史记录的开销。关联任务的变化一起保存，其他任务、未知附加字段和玩家资产保留。请求的 8 秒时限保持。

日志阶段新增 `quest.receipt_lookup`、`quest.definitions`、`quest.operation` 和 `quest.save_delta`，沿用两端关联编号与现有 journal namespace。

## 回归验证

- 使用 769 条状态、4,768 条附加字段的独立 fixture，单个修改由 5,539 次状态/附加字段 SQL 写入降为 4 次；父记录与回执写入另计。
- 延迟注入重现旧逐行写入超时，并验证差量写入在同一预算内完成。
- 一次性 MariaDB 单分片、双分片验证完成、重置、超时回滚、永久回执恢复、幂等和历史/资产保持；现有 HTTP 任务接口回归覆盖预览、提交、分页流水及 PVF 变更。
- 前端回归验证执行中收起、页面刷新恢复、原请求重试，以及多角色部分成功后的重新预览。

源码测试、部署和玩家游戏内验收分别记录于发布回执。
